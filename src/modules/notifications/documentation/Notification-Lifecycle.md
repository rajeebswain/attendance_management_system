# M12 Notification Lifecycle

Module ID: M12

Status: Approved

Purpose: Define the lifecycle of a notification from creation to completion.

---

## Overview

Every notification in ERAxis follows a predictable lifecycle.

The lifecycle is owned by M12 Notifications.

External modules may trigger notification creation but must never manipulate notification status directly.

---

## Lifecycle States

### State 1

Created

Description:

Notification record generated by:

```text
notificationService.dispatch()
```

At this stage:

```text
Notification exists
Status = unread
readAt = null
```

---

### State 2

Unread

Description:

Notification is visible to the user but has not yet been acknowledged.

Properties:

```text
status = unread

readAt = null
```

Examples:

* Leave Approved
* Leave Rejected
* Attendance Correction Approved
* Attendance Correction Rejected

---

### State 3

Read

Description:

User has viewed or explicitly marked the notification as read.

Properties:

```text
status = read

readAt = timestamp
```

Example:

```text
readAt = 2026-06-05T12:30:00Z
```

---

## MVP Lifecycle

```text
Created
   ↓
Unread
   ↓
Read
```

This is the only approved lifecycle for MVP.

---

## Future Lifecycle States

The following states are reserved for future releases.

### Archived

Purpose:

Hide old notifications while preserving history.

Example:

```text
status = archived
```

Not part of MVP.

---

### Deleted

Purpose:

Permanent removal.

Not part of MVP.

Deletion should be controlled by retention policies rather than user actions.

Not part of MVP.

---

## Status Ownership

### M12 Owns

* Notification creation
* Status updates
* Read tracking
* Lifecycle transitions

---

### External Modules Must Not

* Change notification status
* Change readAt
* Delete notifications
* Create notification records manually

---

## Read Transition

Trigger:

```text
Mark Read
```

Transition:

```text
Unread
   ↓
Read
```

Actions:

```text
status = read

readAt = current timestamp
```

---

## Mark All Read

Trigger:

```text
Mark All Read
```

Transition:

```text
All unread notifications
   ↓
Read
```

Actions:

```text
status = read

readAt = current timestamp
```

for every unread notification.

---

## Unread Count Rules

Bell Badge Count:

```text
Count notifications where

status = unread
```

Read notifications must never contribute to unread count.

---

## Retention Strategy

MVP:

```text
No automatic deletion
```

Notifications remain available.

---

## Future Retention

Potential future policies:

```text
90 days

180 days

365 days
```

based on tenant configuration.

Not part of MVP.

---

## Lifecycle Events

Supported transitions:

```text
Created
   ↓
Unread
   ↓
Read
```

Unsupported transitions:

```text
Read
   ↓
Unread

Read
   ↓
Created
```

These transitions are not allowed.

---

## Architecture Summary

MVP Lifecycle:

```text
Created
   ↓
Unread
   ↓
Read
```

This lifecycle is considered stable and should be used by:

* Notification Service
* Repository
* Database Schema
* Notification Center
* Notification Bell
* Future Notification Channels
