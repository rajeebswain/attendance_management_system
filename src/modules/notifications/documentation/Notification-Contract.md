# M12 Notification Contract

Module ID: M12

Status: Approved

Purpose: Define the canonical Notification object used throughout ERAxis.

---

## Overview

Every notification in the system must follow this contract.

All modules creating notifications must use:

```text
notificationService.dispatch()
```

The notification object generated by M12 becomes the single source of truth for:

* Notification Center
* Notification Bell
* Unread Count
* Future Email Notifications
* Future Push Notifications
* Future Notification Analytics

---

## Notification Object

```javascript
{
  id: string,

  tenantId: string,

  userId: string,

  eventType: string,

  title: string,

  message: string,

  category: string,

  status: string,

  priority: string,

  metadata: object,

  createdAt: string,

  readAt: string | null
}
```

---

## Field Definitions

### id

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

Unique notification identifier.

Example:

```text
notif_01JX123ABC
```

---

### tenantId

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

Identifies which tenant owns the notification.

Required for multi-tenant SaaS isolation.

Example:

```text
tenant_001
```

---

### userId

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

Target recipient.

Notifications belong to a single user.

Example:

```text
user_123
```

---

### eventType

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

System event that generated the notification.

Examples:

```text
LEAVE_APPLIED

LEAVE_APPROVED

LEAVE_REJECTED

ATTENDANCE_CORRECTION_SUBMITTED

ATTENDANCE_CORRECTION_APPROVED

ATTENDANCE_CORRECTION_REJECTED
```

---

### title

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

Short notification heading.

Example:

```text
Leave Request Approved
```

---

### message

Type:

```text
string
```

Required:

```text
Yes
```

Purpose:

Human-readable notification content.

Example:

```text
Your Casual Leave request has been approved.
```

---

### category

Type:

```text
string
```

Required:

```text
Yes
```

Allowed Values:

```text
attendance

leave
```

Purpose:

Notification grouping and filtering.

---

### status

Type:

```text
string
```

Required:

```text
Yes
```

Allowed Values:

```text
unread

read
```

Purpose:

Read tracking.

---

### priority

Type:

```text
string
```

Required:

```text
Yes
```

Allowed Values:

```text
low

normal

high
```

Purpose:

Notification importance level.

---

### metadata

Type:

```text
object
```

Required:

```text
No
```

Purpose:

Store event-specific details without changing the contract.

Example:

```javascript
{
  leaveType: "Casual Leave",
  fromDate: "2026-06-10",
  toDate: "2026-06-12",
  approverName: "Manager Name"
}
```

---

### createdAt

Type:

```text
ISO Date String
```

Required:

```text
Yes
```

Purpose:

Notification creation timestamp.

---

### readAt

Type:

```text
ISO Date String | null
```

Required:

```text
Yes
```

Purpose:

Tracks when notification was read.

Example:

```text
null
```

or

```text
2026-06-05T12:30:00Z
```

---

## Ownership Rules

### M12 Owns

* Notification Contract
* Notification Creation
* Notification Storage
* Notification Status
* Notification Lifecycle

---

### External Modules Own

Event generation only.

Examples:

* M04 Attendance
* M07 Leave

External modules must never:

* Write directly to notification storage
* Modify notification status
* Create notification records manually

---

## Approved Lifecycle

```text
Created
   ↓
Unread
   ↓
Read
```

Future phases may introduce:

```text
Archived

Deleted
```

but they are not part of MVP.

---

## Contract Stability

This contract is considered stable.

Changes require architecture review because they affect:

* Database schema
* Notification service
* Repository
* UI
* Future notification channels
